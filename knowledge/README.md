# AI Office Knowledge Base

## Purpose

The knowledge base stores reusable facts, decisions, reference material, and historical context used by AI Office agents and departments.

## Core Principle

Store shared knowledge once.

Agents should reference the knowledge base rather than maintaining duplicate copies of the same information.

## Structure

- dealerships: Dealership profiles, contacts, platforms, offers, and operating details
- vendors: Vendor contacts, services, pricing, contracts, and performance notes
- campaigns: Campaign history, strategy, performance, and lessons learned
- offers: Current and historical promotions, incentives, and disclaimers
- projects: Project-specific background, decisions, and reference material
- creative: Brand rules, creative direction, prompts, and asset documentation
- finance: Financial rules, budgets, plans, and non-secret documentation
- side-hustles: Platform notes, earnings analysis, mileage, and procedures
- technical: Technical notes, troubleshooting, and configuration knowledge
- personal: Approved preferences and planning information
- research: Research notes and source summaries
- archive: Retired or historical knowledge

## Rules

- Never store passwords, access tokens, private keys, or API secrets.
- Clearly identify dates and source material.
- Distinguish verified facts from assumptions.
- Archive outdated knowledge instead of silently deleting it.
- Avoid duplicate documents.
- Use descriptive file names.
